# Brooks GPL

**VS Code에서 Brooks/Precise Automation의 GPL 코드를 작성하고, 제어기에 배포·디버깅할 수 있는 확장입니다.**

GPL(Guidance Programming Language) 코드의 자동완성·탐색부터 프로젝트 관리, 프로그램 실행, 제어기 상태 확인까지 지원합니다.
코드 편집 기능은 제어기 연결 없이도 사용할 수 있습니다.

## 주요 기능

| 기능               | 할 수 있는 일                                                           |
| ------------------ | ----------------------------------------------------------------------- |
| 코드 작성·탐색     | 구문 강조, 자동완성, 매개변수 도움말, 정의·참조 찾기, 이름 바꾸기       |
| 프로젝트 관리      | `.gpr` 소스·라이브러리 인식, 소스 목록 동기화, 제어기 프로젝트 다운로드 |
| 업로드·컴파일·실행 | 소스 업로드, 변경분 컴파일, 업로드 후 실행, Flash 영구 저장             |
| 디버깅             | 중단점, 단계 실행, 스레드·호출 스택·변수 확인, Watch 식 평가            |
| 제어기 모니터링    | 대시보드, 온도·자원·에러 조회, 디지털 I/O, 런타임 콘솔·통신 로그        |
| AI 연동            | MCP 연결 설정 내보내기, 진단 정보 공유, AI를 통한 확장 기능 사용        |

## 지원 환경

- **VS Code 1.74 이상**
- **언어 파일:** `.gpl`, `.gpo`
- **프로젝트:** `Project.gpr`의 소스 목록과 참조 라이브러리
- **제어기:** Brooks/Precise Automation PA 제어기의 명령 콘솔·런타임 콘솔·FTP 연동

제어기 업로드·컴파일·실행·디버깅에는 제어기와의 네트워크 연결이 필요합니다.
GPL 컴파일은 제어기에서 수행하며, 상태 조회 항목은 제어기 모델과 소프트웨어 버전·센서 구성에 따라 달라집니다.

## 설치

확장 ID는 **`nir414.gpl-language-support`**입니다.

VSIX 파일로 설치하려면:

1. 배포받은 `.vsix` 파일을 준비합니다. 릴리스 파일은 [GitHub Releases](https://github.com/nir414/GPL_language/releases)에서 확인할 수 있습니다.
2. VS Code의 확장 화면(`Ctrl+Shift+X`)에서 **… → Install from VSIX…**를 선택합니다.
3. VSIX 파일을 선택하고, 다시 로드 안내가 나오면 창을 다시 로드합니다.

새 VSIX로 업데이트할 때도 같은 방법으로 설치합니다.

## 시작하기

### GPL 코드 편집

`Project.gpr`가 있는 프로젝트 폴더를 VS Code에서 열고 `.gpl` 파일을 선택합니다.
프로젝트의 소스와 참조 라이브러리를 인식해 자동완성·정의 찾기·참조 검색에 사용합니다.
개별 GPL 파일을 열어 편집할 수도 있습니다.

명령은 명령 팔레트(`Ctrl+Shift+P`)에서 `GPL:`을 검색해 실행할 수 있습니다.

### 제어기 연결

1. VS Code 설정에서 `gpl.controller.ip`를 실제 제어기 주소로 지정합니다.
2. `GPL: Connect to Controller`를 실행합니다.
3. 사이드바의 **GPL Controller** 패널에서 스레드·파일·시스템 정보를 확인합니다.

워크스페이스에 프로젝트가 여러 개 있으면 명령 실행 시 대상을 선택할 수 있습니다.
탐색기에서 `.gpr`가 들어 있는 프로젝트 폴더를 우클릭하면 해당 프로젝트로 업로드·배포·디버깅을 실행할 수 있습니다.

## 코드 작성과 탐색

| 기능                | 사용 방법              | 지원 내용                                                           |
| ------------------- | ---------------------- | ------------------------------------------------------------------- |
| 자동완성            | `Ctrl+Space`           | 프로젝트 심볼, 멤버, 로컬 변수, GPL 키워드·타입·연산자              |
| 매개변수 도움말     | 함수 호출 중 표시      | 시그니처, 현재 매개변수, 오버로드별 정보                            |
| Hover               | 식별자에 마우스 올리기 | 타입, 선언, 함수 설명, 매개변수·반환값 문서                         |
| 정의로 이동         | `F12`                  | 함수·클래스·변수의 선언 위치, 문자열로 지정한 `New Thread` 프로시저 |
| 참조 찾기           | `Shift+F12`            | 심볼의 사용 위치 검색                                               |
| 이름 바꾸기         | `F2`                   | 선언과 참조를 함께 변경하며 범위·예약어·이름 충돌 확인              |
| 문서 내 심볼 탐색   | `Ctrl+Shift+O`         | 현재 파일의 Module·Class·프로시저·변수 구조                         |
| 작업 영역 심볼 검색 | `Ctrl+T`               | 프로젝트의 심볼 검색                                                |

- **구문 강조·코드 접기:** 선언, 제어문, 주석과 영역을 구분하고 블록을 접을 수 있습니다.
- **문 스니펫:** `If`, `For`, `Try`, `Select`, `Sub`, `Function` 등을 입력해 코드 골격을 삽입하고 `Tab`으로 입력 위치를 이동합니다.
- **내장 API 도움말:** 주요 GPL 내장 API의 시그니처·설명·공식 레퍼런스 링크를 제공합니다.
- **문서화 주석:** 선언 위에서 `'''`을 입력하거나 `GPL: Insert Documentation Comment`를 실행해 주석 골격을 만듭니다. 작성한 설명은 Hover·자동완성·매개변수 도움말에 표시되며, 오버로드 사이의 공통 설명도 공유합니다.
- **진단과 Quick Fix:** 지원하는 문법·호환성 검사 결과와 수정 제안을 표시합니다. 제어기 컴파일 오류는 **Problems** 패널에서 해당 위치로 이동할 수 있습니다.

## 프로젝트와 프로그램 배포

`Project.gpr`의 소스 목록과 프로젝트 폴더의 파일을 맞추려면 `.gpr` 파일을 우클릭하고
`GPL: Sync Project Sources`를 실행합니다. 파일 추가·이름 변경·삭제 시에도 목록 반영 여부를 확인할 수 있습니다.

프로그램을 제어기에 반영할 때는 목적에 맞는 명령을 선택합니다.

| 명령                    | 동작                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------- |
| `GPL: Upload Only`      | 소스만 업로드합니다. 실행 중 프로그램을 정지하거나 컴파일·실행하지 않습니다.                          |
| `GPL: Quick Compile`    | 변경된 소스를 업로드하고 컴파일합니다. 별도의 정지·실행 명령은 보내지 않습니다.                       |
| `GPL: Deploy`           | 프로젝트를 업로드하고 컴파일합니다. 실행 중인 스레드의 정지가 필요하며, 프로그램은 시작하지 않습니다. |
| `GPL: Upload & Start`   | 소스를 업로드하고 실행 중인 스레드를 정지한 뒤, 컴파일과 실행을 수행합니다.                           |
| `GPL: Start`            | 로컬 소스를 업로드하지 않고, 제어기에 올라간 프로젝트를 컴파일해 실행합니다.                          |
| `GPL: Save to Flash`    | 프로젝트를 Flash에 영구 저장합니다. 전원 차단 금지 표시가 해제될 때까지 기다립니다.                   |
| `GPL: Stop All Threads` | 모든 스레드의 정지를 요청하고, 진행 중이거나 대기 중인 업로드·배포도 취소합니다.                      |

`Upload Only` 뒤에는 컴파일이 필요합니다. `Upload & Start`에서 발생한 컴파일 오류도 Problems 패널에 표시됩니다.
제어기 FTP 트리의 `Compile & Run`은 **이미 업로드된 복사본**을 실행하므로 로컬 수정 사항을 반영하려면 먼저 업로드해야 합니다.

연결 중 파일 저장에 따른 자동 업로드·컴파일은 `gpl.quickCompile.autoOnSave`에서 설정합니다.
`auto` 모드에서는 소스를 업로드하고, 스레드가 완전히 정지해 있을 때만 컴파일합니다.

### 제어기 프로젝트 내려받기

제어기 파일 트리의 `Download`로 프로젝트를 내려받을 수 있습니다.

- **Live Working Copy:** 내려받은 코드를 편집하고 제어기에 다시 반영하는 작업용 복사본입니다. 저장 시 자동 업로드 설정이 적용됩니다.
- **Read-only Snapshot:** 검토용 복사본입니다. 자동 업로드와 배포·컴파일·Flash 저장이 차단됩니다.

다운로드 후 **Controller 작업공간 열기**를 선택하면 내려받은 프로젝트를 한 작업 영역에서 관리할 수 있습니다.

## 디버깅

- **배포하고 디버깅:** 프로젝트 폴더를 우클릭해 `GPL: Debug Project`를 실행합니다. `launch.json`을 직접 작성할 필요가 없습니다.
- **실행 중인 프로그램에 연결:** `GPL: Debug: Attach Only`를 실행합니다.
- **구성 저장:** `GPL: Create/Update launch.json`으로 디버그 구성을 만들고 실행 및 디버그 화면에서 선택합니다.

중단점과 단계 실행, 스레드별 호출 스택, 변수·배열·객체 조회, Watch 식 평가를 지원합니다.
스레드를 고정해 Continue·Step의 대상을 유지하거나, 에디터와 제어기의 중단점을 동기화할 수 있습니다.

| 기본 단축키 | 기능                   |
| ----------- | ---------------------- |
| `F9`        | 중단점 설정·해제       |
| `F5`        | 디버그 시작·계속 실행  |
| `F6`        | 선택한 스레드 일시정지 |
| `F10`       | Step Over              |
| `F11`       | Step Into              |
| `Shift+F11` | Step Out               |

단축키는 VS Code 기본값 기준이며, 사용자 키 바인딩이나 `gpl.keybindings.gdeStyle` 설정에 따라 달라질 수 있습니다.

디버거 **분리(Disconnect)** 시 기본적으로 프로그램 실행은 유지됩니다.
프로그램도 정지하려면 디버그 툴바의 **Stop Debugging (디버그 중지 · 프로그램 정지)** 또는 `GPL: Stop All Threads`를 사용합니다.

참조 라이브러리의 소스에 중단점을 설정할 수 없다면 `.gpl` 파일의
`GPL: Promote Source for Breakpoint`로 메인 프로젝트의 소스에 포함할 수 있습니다. 변경 내용을 확인한 뒤 재배포합니다.

## 제어기 상태와 로그

제어기 패널과 `GPL: Open Controller Dashboard`에서 상태와 로그를 확인할 수 있습니다.

- **상태·자원:** 스레드, 전원·위치, 메모리·자원 사용량과 에러 정보
- **온도:** CPU·앰프 온도, 센서별 추이와 조회 시각. 센서 미지원·미확인 값은 구분해 표시
- **디지털 I/O:** 신호 상태 조회, 번호 검색·필터, 확인 후 강제 ON/OFF·해제
- **런타임 콘솔:** 프로그램 출력과 실행 이벤트 확인
- **통신 모니터·라이브 로그:** 명령 콘솔과 런타임 콘솔의 송수신 확인

`GPL: Open Digital I/O Panel`로 I/O 화면을 바로 열 수 있습니다.
`GPL: Show Traffic Monitor`, `GPL: Start Live Log Terminal`로 통신 기록을 확인하고,
`GPL: Copy Situation for Chat`으로 현재 상태를 복사해 문의에 첨부할 수 있습니다.

## AI 에이전트 연동

MCP를 지원하는 AI 도구에서 확장의 프로젝트 배포·디버깅·상태 조회 기능을 사용할 수 있습니다.
`GPL: Export AI Agent Setup`으로 연결 설정을 내보내고, `GPL: Check AI Agent Setup`으로 구성을 점검합니다.

AI 요청은 VS Code 확장의 제어기 연결을 공유하며, 요청과 응답은 **GPL Language Support** 출력 채널에 표시됩니다.
AI 도구의 MCP 설정과 연결은 별도로 필요합니다.

## 주요 설정

VS Code 설정(`Ctrl+,`)에서 `@ext:nir414.gpl-language-support`를 검색하면 확장 설정을 볼 수 있습니다.

| 설정                          | 용도                                    |
| ----------------------------- | --------------------------------------- |
| `gpl.controller.ip`           | 제어기 IP 주소                          |
| `gpl.controller.port`         | 명령 콘솔 포트                          |
| `gpl.controller.consolePort`  | 런타임 콘솔 포트                        |
| `gpl.quickCompile.autoOnSave` | 파일 저장 시 업로드·컴파일 방식         |
| `gpl.project.autoSyncSources` | 소스 파일 변경 시 `.gpr` 목록 반영 방식 |

전체 옵션과 현재 기본값은 설정 화면에서 확인할 수 있습니다.

## 문제가 생겼을 때

| 증상                               | 확인할 내용                                                                                                      |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 자동완성·정의 찾기가 동작하지 않음 | 파일의 언어 모드가 GPL인지, `.gpr`의 소스·라이브러리 목록이 맞는지 확인하고 `GPL: Refresh Symbols`를 실행합니다. |
| 제어기 연결 실패                   | 제어기 주소, 명령 콘솔·런타임 콘솔·FTP의 네트워크 접근, 방화벽과 다른 프로그램의 접속 상태를 확인합니다.         |
| 업로드·컴파일 실패                 | **출력 → GPL Language Support**, **GPL Deploy (Debug)**와 **Problems** 패널에서 오류를 확인합니다.               |
| 제어기에서 수정 전 코드가 실행됨   | `Start`는 로컬 소스를 업로드하지 않습니다. `Deploy` 또는 `Upload & Start`로 변경 사항을 먼저 반영합니다.         |
