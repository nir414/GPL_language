# 작업 기록 규칙 (ai-handoff · CHANGELOG)

작업을 마칠 때 남기는 기록의 세칙이다. 요약은 루트 `AGENTS.md` §6에 있고, 이 문서가 정본이다.
목적은 하나다: **다음 작업자(사람이든 AI든)가 `AGENTS.md` → `docs/ai-handoff.md` 순서로만 읽어도 맥락과 다음 할 일을
파악할 수 있게 하는 것.** 그래서 필독 문서는 작게 유지하고, 지난 기록은 원문 그대로 아카이브로 옮긴다.

## 1. 문서 배치

| 파일 | 담는 것 | 필독 여부 |
| --- | --- | --- |
| `docs/ai-handoff.md` 헤더·§0·§2·§3 | 직전 세션 요약, 하드 규칙 상세, 사용자 결정 대기, 코드 작업·결정 대기 | 필독 |
| `docs/ai-handoff.md` §4·§5 | 핵심 파일 지도, 정상 응답 원문 | 필요할 때 |
| `docs/ai-handoff.md` §1 | 최근 10개 세션 본문 + 그 세션들의 인덱스 | 배경을 찾을 때 |
| `docs/ai-handoff-verification.md` | 새 VSIX의 실사용·실기·UI 확인 대기 항목 | 사용자가 확인할 때 |
| `docs/archive/handoff/<YYYY-MM>.md` | 옮겨 간 세션 원문, 완료 항목 부록 | 찾을 때 |
| `docs/archive/handoff/index.md` | 아카이브된 세션 전체 인덱스 | 찾을 때 |

`docs/ai-handoff*.md`와 `docs/archive/handoff/`는 MkDocs 사이트에서 제외된다(`mkdocs.yml`의 `exclude_docs`).
새 아카이브 파일을 nav에 등재하지 않는다.

## 2. ai-handoff.md 갱신

- **세션 항목**: §1에 `## 1-XX. YYYY-MM-DD 세션 — 주제` 형식으로 증상(요청) → 원인 → 조치(의도와 방법) → 검증 → 남은 일을 쓴다.
  같은 날 여러 세션이 동시에 기록하므로 쓰기 직전에 파일을 다시 읽어 마지막 번호를 확인한다.
- **인덱스**: §1-0 표에 한 줄(§ 번호 · 날짜 · 주제 · 위치)을 추가한다.
- **헤더**: "최종 갱신", "현재 package 버전", "직전 세션"을 고친다. **직전 세션은 1건만 요약한다.** 이전 요약을 `직전: … 직전: …`으로
  이어 붙이지 않는다(그렇게 쌓여 헤더 한 줄이 16,000자가 됐던 것이 2026-08-31 정리의 직접 원인이다).
- **§1 본문은 최근 10개 세션만 둔다.** 넘치면 오래된 것부터 해당 월 아카이브로 **원문 그대로** 옮기고, 인덱스 행도
  `docs/archive/handoff/index.md`로 옮긴다(위치 칸은 아카이브 링크). §1 머리의 아카이브 범위 표도 함께 고친다.
- **§3에는 코드 작업과 결정 대기만 둔다.** "새 VSIX에서 ①…②… 확인" 같은 실사용·실기·UI 확인 항목은
  `docs/ai-handoff-verification.md`에 넣는다. 둘이 섞여 §3이 133KB(파일의 46%)까지 불었던 것이 2026-11-04 정리의 원인이다.
- **완료(`[x]`)된 항목은 남기지 않는다.** 기록이 필요하면 해당 월 아카이브의 부록으로 옮긴다. 확인이 끝난 검증 항목도 같다.
- **섹션 번호(§0·§1-XX·§2·§3·§3-B·§4·§5)는 바꾸지 않는다.** 소스 주석, `AGENTS.md`, 런북, `package.json` 설정 설명이 참조한다.
  바꿔도 되는 것은 물리적 순서뿐이다. §0 하드 규칙 번호도 `AGENTS.md` §4와 1:1로 유지한다.

## 3. CHANGELOG.md

- 사용자에게 배포한 버전은 항목을 추가한다(형식은 기존 항목을 따른다). 버전 섹션은 최신이 위로 오게 내림차순으로 둔다.
- 내용이 없는 `### Added/Changed/Fixed/Removed` 빈 섹션 헤더는 남기지 않는다.
- 같은 내용이 중복되면 가장 최신 항목만 남긴다. 단, 각 버전 항목은 그 버전의 이력이므로 주제가 겹친다는 이유만으로 과거 버전
  항목을 지우지는 않는다.

## 4. 충돌하는 낡은 기록

옛 서술이 새 결정과 정면으로 충돌하면(같은 사양·상태·규칙을 다르게 말해, 나중에 읽는 사람이 어느 쪽이 맞는지 착각할 수 있으면)
낡은 서술은 지우거나 무효로 표시하고 최신 항목을 가리킨다. 결정의 흐름(무엇을·왜)은 남기되, 지금은 틀린 "현재 사실"을 두 개로
남겨 두지 않는다. 지침 파일(`AGENTS.md`·`.github/instructions/*`)도 같다 — 규칙이 바뀌면 그 규칙을 말하는 모든 곳을 같은 커밋에서 맞춘다.
