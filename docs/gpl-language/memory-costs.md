# 메모리 아끼기 — 항목별 단가와 주의점

PA 제어기는 업로드한 소스, 컴파일 결과, 실행 중 객체와 스레드가 모두 같은 주 메모리를 씁니다. 여유 메모리가 1 MB 아래로 내려가면 Compile·Start 가 실패할 수 있으므로, 큰 프로젝트에서는 아래 단가를 참고해 코드를 씁니다.

!!! note "출처와 한계"
    아래 수치는 Sample Prep 과제에서 GPL 4.2K5 계열 테스트(시뮬레이션) 제어기로 잰 값입니다(2026-11-05~06, DataID 130 의 free·used segments 와 `Show Memory` 차이, 같은 프로브 두 번 ±1 %). Brooks 공식 문서에 있는 값이 아니며, 펌웨어 버전이 다르면 달라질 수 있습니다.

## 1. 어디에 메모리가 드나 — 실행 중인 앱 하나의 예

| 몫 | 크기 |
| --- | --- |
| `/GPL` 에 올린 소스 파일 | 2.39 MB |
| 컴파일 결과 | 4.13 MB |
| 실행 객체 + 스레드 | 0.41 MB |
| 남은 Free | 1.18 MB |

메모리의 대부분은 **코드**입니다(소스 + 컴파일 6.5 MB). 객체 생성·복사·클래스 계층은 상대적으로 작습니다. 그래서 먼저 줄일 곳은 올리는 소스와 컴파일되는 선언입니다.

## 2. 컴파일 결과가 쓰는 메모리 (코드 1개당)

| 항목 | 크기 |
| --- | --- |
| 단순 문장 `x = x + 1` | 66 B |
| 호출 문장 `x = W(x)` | 59 B |
| `If x > n Then x = 0` | 117 B |
| 리터럴 대입 | 글자 수 + 약 25 B |
| 빈 `Sub` | 165 B |
| 인자 1개 빈 `Sub` | 386 B (첫 인자 +221 B) |
| 인자 4개 빈 `Sub` | 691 B (인자당 약 100~130 B) |
| 한 줄 래퍼 `Function`(인자 1개) | 520 B |
| 지역 `Dim` | 87 B |
| 모듈 변수 | 78 B |
| `Const … As Integer` / `As String`(25자) | 150 B / 205 B |
| `Class`(필드 1 + 빈 New) | 430 B |
| `Module`(빈 Sub 1개) | 354 B (껍데기 약 190 B) |
| 주석 | 0 B (업로드한 파일에만 남음 — 파일 크기의 약 1.15배) |

프로시저 머리(정의와 인자)가 컴파일 메모리의 약 3분의 1을 차지했습니다. 본문 한두 줄짜리 공개 래퍼는 문장 7~8줄 값입니다. 반면 호출 한 줄은 59 B 라, 여러 곳에서 실제로 쓰는 공통 함수는 그대로 두는 편이 낫습니다.

### 확장의 배포 전처리로 줄이기

`gpl.deploy.preprocess` 를 켜면 워크스페이스 밖에 만든 사본을 올립니다. 로컬 파일은 그대로이고 줄 번호도 그대로라 오류 위치·중단점이 원본과 같습니다.

| 옵션 | 줄이는 것 |
| --- | --- |
| `stripComments`·`trimWhitespace` | 업로드한 소스(주석·공백) |
| `excludeUnreachableLibraryFiles` | 쓰지 않는 라이브러리 파일(업로드 + 컴파일) |
| `removeUnusedMembers` | 라이브러리 안의 쓰지 않는 선언·지역 `Dim`·빈 Module(컴파일) |

배포 기록(Output)에 "컴파일 메모리 추정" 이 함께 나옵니다. 위 단가로 계산한 추정이며, 실제 값은 Compile 전후 `Show Memory` 로 확인합니다.

## 3. 실행 중에 쓰는 메모리

| 항목 | 크기 |
| --- | --- |
| 빈 클래스 객체 | 40 B (+ 숫자 필드마다 8 B · 참조 필드마다 4 B) |
| 배열 칸 Double·Integer·Boolean / String·객체 참조 | 8 B / 4 B (배열 머리 약 80 B) |
| `String` 0~120자 | 156~180 B (길이와 거의 무관) |
| `String` 128 / 200 / 300 / 500 / 1000자 | 316 / 476 / 796 / 1,116 / 2,418 B |
| 객체의 String 칸에 `""` 넣기 | 칸마다 **+183 B** |
| 같은 문자열을 여러 칸에 대입 | 칸마다 180 B — 복사되고 공유되지 않음 |
| `New Location` / `.Clone()` | 155 / 164 B |
| `New Profile` | 70 B |
| Delegate | 48 B |
| 객체 참조 대입 `b = a` | 0 B |
| `ReDim Preserve`·문자열 이어 붙이기·예외 | 끝난 뒤 남는 것 없음 |

- 객체를 많이 만드는 클래스는 String 필드를 `""` 로 초기화하지 마세요. Nothing 으로 두고 바깥에 돌려줄 때만 빈 문자열로 바꾸면 크게 줄어듭니다(Data_Apon 노드 1,219 → 285 B). 다만 Nothing 인 String 을 ByVal 로 넘기거나 `Len` 에 쓰면 -782 가 날 수 있습니다([common-mistakes 0-5](common-mistakes.md)). 확장은 이 초기화를 정보 진단 `string-field-empty-init` 으로 알려 드립니다.
- 로그 링 버퍼는 항목을 String 한 줄로 두는 편이 가장 작았습니다(256칸 기준 164 B/칸, 객체로 나누면 411 B/칸).

## 4. 스레드

| 경우 | Free 감소 |
| --- | --- |
| 처음 쓰는 스레드(스택 4 / 6 / 8 KB) | 약 37 / 39 / 41 KB — **제어 블록 약 33 KB + 스택** |
| 같은 이름으로 다시 Start | 0 (스택이 커질 때만 차이) |
| Unload 뒤 다시 실행 | 스택만 |

- 스레드 제어 블록(약 33 KB)은 그 부팅 동안 Free 로 돌아오지 않고, 다음에 만드는 스레드가 재사용합니다(관측된 동작, 규칙은 추정).
- 스택 크기 자체는 KB 그대로 듭니다. 실제 최대 사용량(`Show Thread -stack`)보다 크게 잡을 이유는 적지만, 줄여서 얻는 것도 몇 KB 입니다.
- 스레드를 하나 줄이면 첫 부팅 기준 약 37 KB 를 아낍니다. 다만 장치 루프처럼 주기·장애가 독립적인 스레드를 합치면 결합 위험이 커집니다.

## 5. `Mid` 에 임시 문자열을 넘기면 메모리가 새는 현상

`Mid` 의 첫 인자로 **식의 결과(임시 문자열)** 를 넘기고 그 문자열이 120자를 넘으면, 호출할 때마다 메모리가 돌아오지 않았습니다. Unload 해도 회복되지 않았고 재부팅해야 돌아왔습니다(제어기 결함으로 보임).

| 코드 | 1회당 돌아오지 않은 메모리 |
| --- | --- |
| `Mid(CStr(i) & long300, 1, 10)` · `Mid(UCase(var300), 1, 10)` · `Mid(CStr(i) & long300, 5)` | 320 B |
| `Mid(CStr(i) & long1000, 1, 1000)` | 약 1,120 B |
| `t = CStr(i) & long300 : Mid(t, 1, 10)` | 0 |
| `Mid(변수, …)` · `Mid(사용자Function(), …)` | 0 |
| 120자 이하 임시값 | 0 |
| `Len`·`UCase`·`InStr`·`.Substring`·`.Split`·`.Trim`·비교에 긴 임시값 | 0 |

긴 문자열은 변수에 먼저 받은 뒤 `Mid(변수, …)` 로 부르세요. 확장은 `Mid` 의 첫 인자가 `&` 연결이거나 내장 문자열 함수 결과이면 정보 진단 `mid-temporary-argument` 로 알려 드립니다.

## 6. 정리 — 피할 것과 괜찮은 것

- **피할 것:** `Mid(<식·내장 함수 결과>, …)`, 본문 한두 줄짜리 공개 래퍼, 인자 많은 프로시저, 쓰이지 않는 Const, 많이 만드는 객체의 String 칸을 `""` 로 채우기, 같은 글을 여러 칸에 복사, 링 항목을 필드별 String 으로 나누기, 120자 넘는 로그 줄, 스레드를 새로 늘리기.
- **괜찮은 것:** 객체 참조 대입, 클래스로 묶기, Delegate, `ReDim Preserve`, 예외, 문자열 이어 붙이기, 주석(컴파일 0 B), 함수 호출(줄당 59 B).
