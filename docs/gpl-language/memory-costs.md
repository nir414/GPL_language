# 메모리 아끼기 — 항목별 단가와 주의점

PA 제어기는 업로드한 소스, 컴파일 결과, 실행 중 객체와 스레드가 모두 같은 주 메모리(약 16 MB)를 씁니다. 여유 메모리가 1 MB 아래로 내려가면 Compile·Start 가 실패할 수 있으므로, 큰 프로젝트에서는 아래 단가를 참고해 코드를 씁니다.

!!! note "출처와 한계"
    아래 수치는 Sample Prep 과제에서 GPL 4.2K5 계열 제어기(시뮬레이션 제어기 포함)로 잰 값입니다(2026-11-05~06, DataID 130 의 free·used segments 차이). Brooks 공식 문서에 있는 값이 아니며, 펌웨어 버전이 다르면 달라질 수 있습니다.

## 1. 컴파일 결과가 쓰는 메모리

| 항목 | 대략의 크기 |
| --- | --- |
| 빈 `Sub` | 165 B |
| 매개변수 하나 | 130~220 B |
| `Function`(Sub 대비) | +180 B |
| 지역 `Dim` | 87 B |
| 모듈 변수 | 78 B |
| `Const` Integer / String | 150 B / 205 B |
| 문장 한 줄 | 59~140 B |
| `Class` | 약 430 B |
| `Module` | 약 190 B |
| 주석 | 0 B(컴파일 결과에는 없음) |

주석은 컴파일 결과에는 남지 않지만, `/GPL` 에 올린 소스 파일은 메모리에 그대로 남습니다(파일 크기의 약 1.15배). 확장의 배포 전처리(`gpl.deploy.preprocess`)로 주석을 지운 사본을 올리면 이 몫을 줄일 수 있습니다. 쓰지 않는 라이브러리 파일을 빼는 옵션도 함께 있습니다.

## 2. 실행 중에 쓰는 메모리

| 항목 | 대략의 크기 |
| --- | --- |
| 객체 하나 | 40 B + 숫자 필드마다 8 B · 참조 필드마다 4 B |
| `String`(120자 이하) | 약 180 B — 대입하면 복사되고 공유되지 않습니다 |
| `String` 128 / 200 / 300 / 1000자 | 316 / 476 / 796 / 2,418 B |
| `Location` | 155 B |
| `Profile` | 70 B |
| Delegate | 48 B |

## 3. 스레드

| 스택 크기 | 새 이름으로 시작할 때 |
| --- | --- |
| 4 / 5 / 6 KB | 약 4.3 / 5.4 / 6.4 KB |
| 8 KB | 28~41 KB(같은 이름으로 다시 시작하면 8.4 KB) |
| 16 KB | 약 49.5 KB |

끝난 스레드의 메모리는 **같은 이름으로 다시 Start 할 때만** 재사용됐습니다. 스레드 이름을 매번 새로 만들면(예: 번호를 붙인 이름) 메모리가 계속 줄어듭니다. 반복해서 띄우는 스레드는 같은 이름을 쓰세요.

## 4. `Mid` 에 임시 문자열을 넘기면 메모리가 새는 현상

`Mid` 의 첫 인자로 **식의 결과(임시 문자열)** 를 넘기고 그 문자열이 120자를 넘으면, 호출할 때마다 메모리가 돌아오지 않았습니다. Unload 해도 회복되지 않았고 재부팅해야 돌아왔습니다.

| 코드(200번 반복) | 1회당 돌아오지 않은 메모리 |
| --- | --- |
| `s = Mid(CStr(i) & long300, 1, 10)` | 320 B |
| `t = CStr(i) & long300 : s = Mid(t, 1, 10)` | 0 |
| `s = Mid(long300, 2, 250)`(변수) | 0 |
| `s = Mid(CStr(i) & short60, 1, 10)`(120자 이하) | 0 |
| `Len`·`UCase`·`InStr`·비교에 같은 임시식 | 0 |

긴 문자열을 다룰 때는 변수에 먼저 받은 뒤 `Mid(변수, …)` 로 부르세요. 확장은 `Mid` 의 첫 인자가 `&` 연결이나 문자열 함수 결과이면 정보 수준 진단(`mid-temporary-argument`)으로 알려 드립니다.
